# مصادر البيانات والكتالوج الديناميكي — Boat Two

## الاستخدام

1. افتح **التجارة ← مصادر البيانات**. في شاشة كتالوج المنتجات المباشرة تظهر مصادر البيانات داخل الصفحة نفسها.
2. أنشئ مصدرًا باسم مفهوم، واختر **Excel / CSV** أو **Google Sheets**.
3. للملفات: ارفع `.xlsx` أو `.csv` وحدد ورقة العمل. التحديث اللاحق يتم برفع الملف الأحدث إلى **المصدر نفسه**.
4. لـGoogle: اربط الحساب للقراءة، ثم اختر الملف وورقة العمل أو النطاق واعرض الأعمدة. يمكنك لصق رابط الشيت الخاص بدل اختيار الملف. الشيت لا يحتاج أن يكون عامًا.
5. اربط عمود **المعرف الثابت** وعمود الاسم، وأضف اختياريًا الوصف والقسم والظهور وترتيب العناصر وترتيب الأقسام والصورة والرابط. استخدم `قسم رئيسي/قسم فرعي` للأقسام الفرعية.
6. اختر الحقول المعتمدة للعرض وسمِّها كما يناسب نشاطك. نوع «سعر كما هو مكتوب» يحتفظ بالنص؛ لا يجري حسابًا أو تحويل عملات أو استنتاج توافر. أسعار الغرف والأطفال والأحجام والألوان تستخدم المحرك نفسه.
7. احفظ الربط، ثم اضغط **مزامنة الآن ومعاينة التحديث**. راجع العدد والعينة والأخطاء والصفوف المفقودة. اضغط **تطبيق التحديث المعروض** لنشر المحتوى.
8. في مصمم البوت، أضف عقدة **كتالوج / أقسام المنتجات** واختر **قسم ديناميكي من مصدر بيانات**. اختر المصدر، ثم قسمًا محددًا أو «قائمة الأقسام تلقائيًا». حدد الحقول المسموح عرضها ورسالة عدم وجود نتائج. يمكن ربط البحث بمتغير مثل `{{search}}`.
9. وصّل المخرج التالي بتحويل للموظف أو ببقية المحادثة. الاختيار يعرض التفاصيل الحالية ويسجل الاستفسار في CRM والملاحظات ثم يتابع المسار. معلومات العميل تحفظها عقد الأسئلة الحالية.
10. احفظ الـFlow وانشره بالطريقة الحالية. إضافة العناصر وتغيير أسعارها وإخفاؤها لاحقًا تتم بالمزامنة دون إعادة نشره.

## قواعد التحديث

- قيم الظهور: `true / false`، `1 / 0`، `yes / no`، `visible / hidden`، `published`، `ظاهر / مخفي`، `نعم / لا`. عند ربط عمود الظهور يجب أن تكون حالته صريحة في كل صف. بدونه تُنشر كل العناصر المستوردة.
- المعرف ثابت داخل المصدر. تعديل السعر أو الاسم يحدث العنصر نفسه؛ تغيير المعرف ينشئ عنصرًا مختلفًا.
- المخفي ممنوع من القوائم والبحث والمساعد والتفاصيل عبر زر قديم.
- الصف المفقود لا يحذف نهائيًا ولا يؤرشف إلا بتأكيد **راجعت الملف الكامل وأريد أرشفة الصفوف المفقودة** في المعاينة اليدوية.
- المزامنة التلقائية لـGoogle فقط، كل 15 دقيقة تقريبًا؛ لا تؤرشف المفقود مطلقًا. تطبق الإخفاء الصريح بعد نجاح التحقق.
- الفشل أو الأعمدة المتغيرة أو تكرار المعرف أو فساد صف يمنع استبدال النسخة السليمة. تظهر حالة الخطأ وسجل المحاولة، مع توضيح عرض آخر نسخة سليمة عند فشل التحديث.
- المعاينة صالحة ساعة ومربوطة بمراجعة المصدر. تغيير الإعدادات أو تطبيق تحديث آخر يمنع تطبيق معاينة قديمة.
- حد الملف 5 MB، والدفعة 10,000 صف و100 عمود و40 حقلًا معتمدًا. حد فك ضغط XLSX هو 25 MB و500 مدخل. تُرفض صيغ XLSX؛ استبدلها بقيم قبل الرفع. CSV بصيغة UTF-8، ولا تنفذ نصوصه كصيغ أو HTML.
- القوائم تعرض 8 عناصر للصفحة، أو 7 عند إضافة الرجوع للأقسام، ولا تتجاوز 10 خيارات مع التنقل.

## المساعد

فعّل **اعتماد الكتالوج لردود المساعد** للمصادر المطلوبة، مع تشغيل المساعد نفسه. يظل تعطيل الوكيل الحالي محترمًا.

يبحث هذا الوضع في الصفوف الحالية للشركة ويعرض النصوص والأسعار المعتمدة مباشرة. لا يرسل نص الشيت إلى نموذج لينفذ تعليماته، ولا يعتمد على أسعار قديمة من المعرفة، ولا يستدعي مزود AI مدفوعًا لإنتاج الأسعار. غياب المعلومة يؤدي لرسالة مختصرة وتحويل للموظف، دون استنتاج توافر أو حساب سعر.

البحث نصي محافظ مع توحيد الحروف العربية وكلمات السؤال الشائعة ومطابقة مستقلة للمقاسات `L / XL / XXL`. ليس محرك توصيات دلاليًا عامًا أو محرك تسعير وحسابات. عند عدم التطابق يتحول للموظف. تفعيل هذا الوضع يجعل ردود الوكيل تعتمد الكتالوج بدل مزج المعرفة القديمة؛ إيقافه يعيد وضع المعرفة المعتاد.

## الأمان

الربط والتعديل والاستيراد والمزامنة والمعاينة الإدارية للمالك والمدير فقط. قراءة البوت محصورة في شركته والعناصر الظاهرة والحقول المعتمدة. Google يستخدم تشفير AES-GCM الحالي وحالة OAuth أحادية الاستخدام. الربط الجديد يطلب Sheets readonly وDrive metadata readonly لاختيار الملفات، دون تعديل الملفات. الاتصالات القديمة ذات الأغراض الأخرى باقية.

لا حجز مؤكد أو مخزون أو خصم مقاعد أو تعديل مالي أو إرسال لعملاء حقيقيين ضمن هذه الإضافة.

## المعاينة محليًا

استخدم متغيرات التطوير الموثقة بالمشروع. احتفظ بـ`EXTERNAL_DELIVERY_ENABLED=false` و`AI_PROVIDER_CALLS_ENABLED=false` للاختبار المعزول، ولا تستبدل أسرار البيئة الحالية.

```bash
pnpm install --frozen-lockfile
pnpm --filter api build
pnpm --filter web build
pnpm migrate
pnpm dev:api
# في طرفية أخرى:
pnpm dev:web
```

`pnpm migrate` يحتاج `.env` و`DATABASE_ADMIN_URL` لقاعدة التطوير المحددة. طبّق migrations السابقة بالترتيب ثم `095_smart_data_sources.sql`. تجربة Excel والمحاكي لا تحتاج إعداد Google.

بعد البناء وتثبيت Playwright ومتصفح Chromium يمكن إعادة القبول المعزول:

```bash
node scripts/run-smart-data-acceptance.cjs
```

يدعم الاختبار `BOAT_PLAYWRIGHT_MODULES` و`BOAT_CHROMIUM_PATH` إذا كان التثبيت خارج المسار المعتاد. يستخدم Next الإنتاجي وNest وPostgreSQL/PGlite وحسابات اصطناعية على 3000 و4000، دون قاعدة إنتاج أو Google أو WhatsApp حقيقي.

## النشر اليدوي على Railway

لم يُنفذ نشر أو تغيير إعدادات Railway. للمالك عند اتخاذ قرار النشر:

1. راجع الـPR، وخذ نسخة احتياطية من PostgreSQL وحدد API وweb والبيئة الحالية. أبقِ Auto Deploy معطلًا.
2. اختر commit التسليم من `feat/smart-data-sources-20261030` كمصدر للخدمتين؛ لا تنشئ مشروعًا جديدًا أو تستبدل المتغيرات الحالية.
3. احتفظ بجذر مستودع العمل المشترك. API: بناء `pnpm --filter api build` وتشغيل `pnpm --filter api start`. الواجهة: بناء `pnpm --filter web build` وتشغيل `pnpm --filter web start`. احتفظ بإعدادات المنافذ الحالية؛ API يستخدم `API_PORT` والواجهة تستخدم 3000 في سكربت المشروع.
4. قبل إتاحة API الجديد، طبّق migration 095 بمهمة إدارية على قاعدة البيئة نفسها. المشغل: `apps/api/src/database/migrate.ts`. في حاوية بها المصدر وtsx ومتغيرات Railway استخدم `pnpm --filter api exec tsx src/database/migrate.ts`. يحتاج `DATABASE_ADMIN_URL` إداريًا؛ التطبيق يستخدم `DATABASE_URL` بدور التطبيق. إذا كانت صورة النشر تحذف المصدر أو SQL أو أدوات التطوير، استخدم مهمة الترحيل المعتمدة الحالية؛ tsc لا ينسخ SQL إلى dist.
5. انشر الخدمتين يدويًا وانتظر `SUCCESS` لكل Deployment، ثم تحقق من `/health` ومصادر البيانات والمصمم والمحاكي. `QUEUED` أو نجاح البناء وحده ليس نجاح نشر.
6. لاختبار Google الحي: جهز OAuth client وواجهتي Sheets وDrive metadata، وسجل `${PUBLIC_API_URL}/integrations/google/callback`. احفظ `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` بسرية وأبقِ `ENCRYPTION_KEY` ثابتة.
7. بوابة Google الحالية تعتمد `EXTERNAL_DELIVERY_ENABLED`، وهي مشتركة مع آثار خارجية أخرى. لا تفعّلها لتجربة Excel؛ راجع القنوات الحالية قبل تفعيلها. لم تتغير هذه البوابة. `AI_PROVIDER_CALLS_ENABLED` لا يلزم لردود الكتالوج المباشرة.
8. اختبر شيتًا وحسابًا تجريبيين مفوّضين. عند التراجع إلى كود أقدم أوقف المزامنة التلقائية واحتفظ بالجداول المضافة؛ لا تحذف بيانات أو سجلات العملاء.
