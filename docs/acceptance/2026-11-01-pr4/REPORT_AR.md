## اختبارات التطبيق الكامل

شُغّل Nest AppModule كاملًا، بلا استبدال controllers أو خدمات CRM/Inbox/الفريق/الحملات باستجابات وهمية. طُبقت ملفات SQL الـ98 الأصلية على PostgreSQL المضمن PGlite مع vector وpgcrypto. النقل لقاعدة البيانات فقط مُكيّف، مع تشغيل app_user غير المالك وفرض RLS. هذه ليست قاعدة Railway أو PostgreSQL 16 عبر الشبكة؛ اختلاف البنية موثق.

ثلاث شركات مستقلة: سياحة، مطعم، متجر. لكل منها تسجيل فعلي عبر واجهة المتصفح وإعداد وكتالوج وبوت وقناة Webchat محلية.

المسارات الناجحة:

1. تسجيل شركة من الواجهة والوصول إلى الإعداد؛ التأكد أن /flows و/commerce/sources فارغان وأنه لا يوجد بوت سياحي تلقائي.
2. إنشاء قناة اختبار، رفع ملف CSV، اكتشاف الأعمدة، اختيار السعر، معاينة وتطبيق بيانات العميل عبر الواجهة.
3. حفظ ونشر بوت وربطه بقناة الاختبار فقط، وفتح المحرر وزر النشر. إعداد الرسم يتم عبر API الحقيقية، والتحرير والمراجعة من UI.
4. تعديل مصدر داخل المحرر؛ تأكيد تجاهل/الاحتفاظ بتعديل غير مطبق؛ تحديث السعر من 100 إلى 125 عبر نافذة المصدر والتحقق من احتفاظ العقدة بالقسم والحقول.
5. إنشاء عميل CRM من قائمة الإدارة والواجهة والتحقق من ظهوره ببيانات فعلية.
6. إنشاء رابط دعوة موظف من الواجهة دون بريد خارجي، قبول الدعوة محليًا، وفحص منع الموظف من دعوة أعضاء آخرين (403).
7. استقبال رسالة من Webchat محلية عبر المسار الحقيقي وإنشاء محادثة؛ فتح Inbox، والاستلام والإعادة للبوت وإضافة ملاحظة عبر API الحقيقية. لم يُرسل رد خارجي أو رسالة لعميل حقيقي، والمعالجة الخلفية الآلية متوقفة في بيئة الاختبار.
8. إنشاء حملة من الواجهة، مراجعة الجمهور وكتابة المحتوى وحفظها كمسودة؛ التحقق من حالة draft، دون جدولة أو إرسال.
9. منع الوصول إلى مصدر وتدفق وعميل شركة أخرى (404)، مع مراجعة الصفحات الأساسية للمشتركين الثلاثة.
10. الإنجليزية على الكمبيوتر، والعربية RTL والموبايل على مدير البوت والقنوات وCRM والحملات والإعدادات؛ لا تجاوز أفقي للصفحة ولا page errors في المسار.
