## نتائج الاختبار

- `corepack pnpm --filter api build`: ناجح.
- `corepack pnpm --filter web build`: ناجح.
- ESLint للملفات المتغيرة: ناجح.
- API suite عبر `node --import tsx --test src/**/*.test.ts`: 150 ناجح، 0 فشل. استخدمت متغيرات اعتماد محلية للاختبار فقط.
- اختبارا `bot-settings.test.ts`: 2 ناجحان؛ تحقق من التحقق من البيانات، عزل tenant، عدم الكتابة فوق إعدادات القناة القديمة، ودور owner/admin للمسارات.
- `pnpm --filter api test` القياسي تعذر بسبب رفض البيئة إنشاء IPC pipe (`EPERM`)؛ شُغلت المجموعة مباشرة بواسطة Node بعد ذلك.
- لم تُنفذ مقارنة صور قبل/بعد، ولم تُختبر العربية RTL أو الإنجليزية LTR، اللابتوب أو الهاتف، إعادة التحميل من واجهة Boat Two، الإلغاء في واجهة Boat Two، أو تراجع Flow Builder وInbox وCRM وSmart Assignment.
- لم يُجر اختبارًا حيًا على السيرفر لتغيير دور Agent/Viewer. وجود `@Roles('owner','admin')` واختبار metadata لا يعادلان اختبار طلب HTTP مرفوض.

## ما يمنع النشر الآن

1. لم تُثبت بعد صور التطابق لنفس viewport وحالة الصفحة، لأن تغييرات هذا الفرع لم تُنشر إلى معاينة قابلة للمقارنة.
2. لا يمكن اعتبار toggles المحجوبة تنفيذًا وظيفيًا؛ Webhook وBusiness Hours وEmail وSMS وGoogle وموفرو Auto Responder تحتاج عقود تشغيل/مزود حقيقية.
3. يجب دمج Shared Inbox مع إعدادات Inbox الحالية بدل حفظ خيارات مكررة لا يستخدمها وقت التشغيل.
4. لا يوجد دليل UI لإعادة التحميل/الإلغاء أو للاختبار على RTL/LTR والموبايل، ولا نفي مستقل للتراجعات في الأقسام المطلوبة.
5. لذلك لم يُنشأ Railway deployment، ولم تُعلن أي حالة PASS للمطابقة البصرية أو التشغيلية.
