# مطابقة محرر CRM داخل المحادثة

تم فتح محرر CRM الأصلي داخل BotSailor مباشرة وقراءة حقوله ثم الإلغاء دون حفظ: Pipeline، Stage، Active Deal، Deal Value/Currency، Expected Close، Deal Owner، Lead Score (Hot/Warm/Cold)، Source.

## التنفيذ
- مكون مستقل InboxCrmOverview يحول نفس بطاقة CRM إلى نموذج تحرير داخلي مع إلغاء/حفظ، دون فتح صفحة أخرى. رابط لوحة CRM مستقل عن زر التحرير.
- اختيار المسار يحدّث المراحل؛ اختيار مسؤول من أعضاء مساحة العمل؛ دعم العملات، القيمة بالوحدات الصغرى الصحيحة، موعد الإغلاق، الاهتمام والمصدر.
- عند غياب مسارات مبيعات، يمكن حفظ الاهتمام والمصدر دون إنشاء صفقة وهمية. لا إنشاء تلقائي لمسارات أو بيانات تجريبية.
- endpoint جديد PATCH /crm/contacts/:id/overview بصلاحيات owner/admin؛ تحديث الصفقة وسمات العميل في transaction واحدة، مع حفظ الحقول الأخرى، والتحقق من نسخة العميل والصفقة والمسار والمرحلة والمسؤول وعزل الشركة.
- migration 092 تضيف عمود expected_close date فقط؛ جُرّبت مرتين على PostgreSQL.
- ترتيب أقفال المسار قبل الصفقة لتوافق عمليات إدارة المسارات؛ أي فشل في التحقق من سمات العميل يعيد تغيير الصفقة أيضًا.

## التحقق
API build وWeb build وESLint وdiff check نجحت. 10 اختبارات PostgreSQL ناجحة تشمل إنشاء وتعديل الصفقة، صفر القيمة، مسح موعد الإغلاق، رفض النسخة القديمة والمسار الأجنبي والعميل الأجنبي، واختبار rollback حقيقي عند فشل سمات العميل.

الدخول السابق توقف من جهة المستخدم وانتهت جلسة المتصفح؛ الفحص المرئي للنسخة الجديدة غير مكتمل حتى تتوفر جلسة دخول. لا ادعاء باختبار الحفظ على الحساب الحقيقي. لا إرسال أو تعديل بيانات عملاء حقيقية.

لا تزال وظائف AI والترجمة والجدولة الفردية وبعض تفاصيل المرجع خارج هذه الدفعة. لا ادعاء باكتمال تطابق المنصة.
